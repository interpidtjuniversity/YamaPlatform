## 业务检查结论

整体业务可以实现，但原描述中有几处需要修正或明确。根据你的选择，最终规则如下：

1. **`classId` 始终不能为空**。
   - 班级公共视频：`class_id != null, group_id = null, exam_name = null`
   - 分组公共视频：`class_id != null, group_id != null, exam_name = null`
   - 测试视频：三个字段都非空
2. 字段名使用 **`groupId` / `group_id`**，修正原描述里的 `grouoId`。
3. 保存接口增加必填 `scriptName`。服务端校验：
   - `scriptName` 属于当前登录用户；
   - 对应任务状态为 `COMPLETED`；
   - 数据库中存在非空 `video_url`。
4. 请求仍保留 `videoUrl`，但不信任前端值：它必须与 `video_conversation_records.video_url` 一致，最终保存数据库中的规范 URL。
5. 保存是**整个 scriptName 当前绑定状态的覆盖**：同一事务内先删除该视频全部旧绑定，再批量插入新绑定。空列表表示清除全部绑定。
6. 查询接口返回当前 owner 的**全部班级 → 分组 → 测试树**。
7. 父节点采用“后代带动父选中”，但为避免丢失“直接绑定”和“后代被绑定”的区别，每个班级/分组节点同时返回：
   - `selected`：自身或任一后代已绑定；
   - `directlyBound`：表 X 中存在该节点本身的精确公共绑定。
   测试叶节点的 `selected` 等于精确三元组是否存在。
8. `ownerNumber`、`classId/groupId/examName` 的归属都由服务端校验，不能只信任请求。
9. 同一 `examName` 可以出现在不同 group 中，叶节点身份使用 `(classId, groupId, examName)`，不能只按 examName 判断。

### 一个后续业务点

当前项目的学生分组是 `group_instance(group_id, exam_name)` 的测试快照。以后实现“学生查看分组公共视频”时，还需要明确分组公共视频究竟按 `exam_name='default'` 的默认成员，还是按当前测试的动态成员判断。本次两个教师端绑定接口不依赖这一规则，不阻塞实现。

## 1. 建表语句

表名采用 `generated_video_bindings`。除你要求的字段外，增加本地视频任务外键和时间字段：

```sql
create table generated_video_bindings (
    id                    bigint generated always as identity primary key,
    video_conversation_id bigint       not null,
    owner_number          varchar(64)  not null,
    class_id              integer      not null,
    group_id              integer,
    exam_name             varchar(255),
    script_name           varchar(255) not null,
    video_name            varchar(255) not null,
    video_url             text         not null,
    created_at            timestamptz  not null default now(),
    updated_at            timestamptz  not null default now(),

    constraint fk_generated_video_conversation
        foreign key (video_conversation_id)
        references video_conversation_records(id)
        on delete cascade,

    constraint ck_generated_video_binding_level check (
        not (group_id is null and exam_name is not null)
    )
);

-- 一个视频在一个班级只能有一条“班级公共空间”记录
create unique index uk_generated_video_class_binding
    on generated_video_bindings(video_conversation_id, class_id)
    where group_id is null and exam_name is null;

-- 一个视频在一个分组只能有一条“分组公共空间”记录
create unique index uk_generated_video_group_binding
    on generated_video_bindings(video_conversation_id, class_id, group_id)
    where group_id is not null and exam_name is null;

-- 一个视频对同一个班级+分组+测试只能绑定一次
create unique index uk_generated_video_exam_binding
    on generated_video_bindings(video_conversation_id, class_id, group_id, exam_name)
    where group_id is not null and exam_name is not null;

create index idx_generated_video_script_name
    on generated_video_bindings(script_name);

create index idx_generated_video_class_exam
    on generated_video_bindings(class_id, group_id, exam_name);

create index idx_generated_video_owner
    on generated_video_bindings(owner_number);
```

`video_conversation_id` 作为真正外键，`script_name` 仍按你的要求冗余保存，方便查询和排查。

> 当前 `VideoConversationDao` 已经读写 `analysis_info`。若数据库尚未增加该列，还需要先执行：
>
> ```sql
> alter table video_conversation_records
>     add column if not exists analysis_info text;
> ```

## 2. PostgreSQL 事务支持

当前 `PostgresConfig` 只有 `pgDataSource` 和 `pgJdbcTemplate`，项目现有默认事务管理器连接的是 MySQL。直接使用无限定的 `@Transactional` 无法保证 PostgreSQL 的 delete + insert 原子性。

将在 `PostgresConfig` 新增：

- `pgTransactionManager`
- `pgTransactionTemplate`

覆盖保存服务使用 `@Qualifier("pgTransactionTemplate")`，事务流程为：

1. 按 `userId + scriptName` 查询并 `FOR UPDATE` 锁定视频任务；
2. 校验 `COMPLETED` 和规范 `videoUrl`；
3. 删除该 `video_conversation_id` 的全部旧记录；
4. 批量插入新记录；
5. 任一插入失败，整个 PostgreSQL 事务回滚，旧绑定不会丢失。

并发覆盖同一视频时，`FOR UPDATE` 保证两个请求串行执行，最终完整状态一定属于其中一个请求，不会混合。

## 3. 请求/返回模型

### 保存请求

```json
{
  "scriptName": "Scene_xxx",
  "videoName": "牛顿第二定律讲解",
  "videoUrl": "http://47.108.214.199:5000/get_video?script_name=Scene_xxx",
  "classInfo": [
    {
      "classId": 1,
      "groupInfo": []
    },
    {
      "classId": 2,
      "groupInfo": [
        {
          "groupId": 22,
          "examNameInfo": []
        },
        {
          "groupId": 23,
          "examNameInfo": ["test1", "test2"]
        }
      ]
    }
  ]
}
```

展开规则严格对应你的示例，共生成 4 行：

```text
(class=1, group=null, exam=null)
(class=2, group=22, exam=null)
(class=2, group=23, exam=test1)
(class=2, group=23, exam=test2)
```

重复输入会先在内存按精确路径去重。以下情况直接拒绝整个请求，不执行删除：

- classId 不属于当前登录 owner；
- groupId 不属于对应 classId；
- examName 不存在于对应 group 的 `group_exam_meta`；
- group 为空却传 examName；
- scriptName 不属于当前用户或视频未成功生成；
- videoName 为空；
- 请求 videoUrl 与任务表规范 URL 不一致。

### 查询树返回结构

```json
{
  "scriptName": "Scene_xxx",
  "videoName": "牛顿第二定律讲解",
  "videoUrl": "...",
  "classInfo": [
    {
      "classId": 2,
      "className": "二班",
      "selected": true,
      "directlyBound": false,
      "groupInfo": [
        {
          "groupId": 23,
          "groupName": "23组",
          "selected": true,
          "directlyBound": false,
          "examNameInfo": [
            {"examName": "test1", "selected": true},
            {"examName": "test2", "selected": false}
          ]
        }
      ]
    }
  ]
}
```

当只绑定 `2班 → 23组 → test1` 时：

- test1：`selected=true`
- 23组：`selected=true, directlyBound=false`
- 2班：`selected=true, directlyBound=false`

如果另有 `(2, null, null)` 记录，则 2班同时为 `selected=true, directlyBound=true`。

### PostgreSQL DAO

新增：

  - `deleteByVideoConversationId`
  - `batchInsert`

### MySQL 层级查询

新增专用只读 MyBatis DAO/Mapper，通过一次左连接查询当前 owner 的完整层级：

```text
class_info
LEFT JOIN group_class_info
LEFT JOIN group_exam_meta
```

这样避免按每个班级、每个分组循环查库，也绕开现有 DAO 中 `LIMIT 100/1000` 造成“全部班级树”被静默截断的问题。

服务层将扁平结果重建为稳定排序、去重后的三级树，并构建三个合法路径集合：

- owner 的 classId 集合；
- `(classId, groupId)` 集合；
- `(classId, groupId, examName)` 集合。

保存接口使用这些集合一次性完成权限和路径合法性校验；查询接口使用同一树作为记录 B，再把 PostgreSQL 绑定记录标记进去。

## 6. 同时修复的现有阻塞问题

当前代码存在两个确定的 JDBC 参数顺序错误，会导致任务无法正确完成/失败落库，而新绑定接口又要求任务必须为 `COMPLETED`，因此必须一并修复：

1. `VideoConversationDao.markCompleted` SQL 参数应为：

```text
code, videoUrl, analysisInfo, id, leaseToken
```

当前错误顺序是：

```text
code, videoUrl, id, leaseToken, analysisInfo
```

2. `VideoConversationDao.markFailed` SQL 参数应为：

```text
code, errorCode, errorMessage, analysisInfo, id, leaseToken
```

当前错误顺序是：

```text
code, errorCode, errorMessage, id, leaseToken, analysisInfo
```

这两处会作为本次实现的前置修复。
